一眼看懂：這支影片最重要的 8 點

  1. 學習歷程要先讓人快速知道「這份作品在做什麼」。
    摘要、研究動機、研究目的與課程脈絡應放在前面，因為教授不一定會逐字閱讀整份檔案。

  2. 把「證明」改寫成自己真正看懂的版本。
    陳仲肯不是直接複製網路證明，而是先閱讀、把不懂的地方弄清楚，再用自己的理解重新寫一次。

  3. 程式驗證能把抽象數學轉成可操作證據。
    例如讓使用者輸入一個正整數，程式實際輸出它如何表示成四個整數平方和，讓理論不只停在「存在性」。

  4. 作品最好能跟目標科系產生真實連結。
    他特別標出自己負責程式部分，對資工系教授而言，這會比只寫「我對資工有興趣」更有說服力。

  5. 學習歷程不是只為升學而做。
    如果還不知道目標科系，也可以從自己的興趣出發；NBA 球鞋、材料、運動、音樂等興趣都可能轉成可研究的主題。

  6. 課程沒有作業，不代表不能做學習歷程。
    線性代數課沒有大型作業，他就把自己真正學到、覺得有意思的概念整理成一份作品。

  7. 脈絡一定要交代清楚。
    教授需要知道：這是什麼課？老師要求什麼？你做了哪些部分？為什麼這樣做？不然內容再多也會讓人看不懂。

  8. 學習歷程仍要做，但不要忽略真正的學科能力。
    他提醒，像臺大電機／資工仍高度重視二階筆試，因此學習歷程不能取代實力；兩者都要準備。

作品案例：四平方和

陳仲肯學長的流程大致是：

找題目 → 讀網路證明 → 弄懂不清楚處 → 用自己的方式重寫 → 寫程式驗證 → 整理成報告

內容包含： - 題目敘述 - 摘要 - 課程與作業背景 - 研究動機 - 研究目的 - 完整證明 - 參考資料 - 程式碼 - 個人分工

這份作品做得好的地方

1. 證明不是直接貼上

把容易困惑的地方重新說清楚，能看出真正理解過。

2. 有程式驗證

讓「四平方和一定存在」進一步變成：

具體輸入 n → 找出實際四個整數

3. 清楚標示個人貢獻

團體作品中明確寫出：

我負責程式部分

這讓審查者能辨認個人能力。

4. 跟資工方向有一致性

數學題目＋程式驗證，自然連結到資訊工程。

可以改進的地方

  • Overleaf／LaTeX 中文字型顯示曾有問題，當時沒有完整解決。
  • 題目不是原創，研究延伸空間有限。
  • 如果能在證明之外加入更深入的改寫、推廣、不同算法比較或效能分析，會更完整。

可重複使用的學習觀念

1. 「看懂」比「找到答案」重要

正確流程：

查資料 → 看不懂 → 拆解 → 弄懂 → 自己重寫

而不是：

查資料 → 複製貼上

2. 理論＋實作會比單一形式更有說服力

例如：

數學證明 + 程式驗證
科學理論 + 實驗
歷史論點 + 資料視覺化

3. 團體作品一定要標示自己的部分

至少回答： - 我負責什麼？ - 我解決了什麼問題？ - 我學到什麼？ - 如果重做一次，我會怎麼改？

4. 興趣可以直接變成學習歷程題目

不一定要先有科系，再找作品。

也可以：

興趣 → 問題 → 查資料 → 分析 → 作品 → 再反推自己適合什麼方向

5. 「沒有作業」不是理由

課堂只要真的有學到東西，就可以自己整理： - 一個核心概念 - 一個延伸問題 - 一份筆記 - 一個小程式 - 一次證明 - 一個案例分析

6. 摘要與脈絡要優先

教授閱讀時間有限。

建議開頭固定有： 1. 這是哪一門課？ 2. 題目是什麼？ 3. 我做了什麼？ 4. 我負責什麼？ 5. 最重要的成果是什麼？

7. 跟科系連結最好用「證據」，不要只寫動機

比起：

我很喜歡資工。

更有力的是：

我用程式解決了一個數學問題，而且能說明我寫了什麼、怎麼驗證。

8. 學習歷程不能取代基本學力

作品再漂亮，也不能忽略： - 課業 - 筆試 - 學科實力 - 解題能力

可直接套用的「數學／程式實作」模板

  1. 課程背景
  2. 問題敘述
  3. 為什麼選這題
  4. 我一開始怎麼理解
  5. 哪裡看不懂
  6. 我查了哪些資料
  7. 我怎麼重新整理／證明
  8. 我寫了什麼程式
  9. 程式如何驗證理論
  10. 個人分工
  11. 遇到的錯誤
  12. 修正方法
  13. 最後結果
  14. 可以延伸什麼
  15. 與未來方向的關聯
